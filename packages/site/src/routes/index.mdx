## Features

> **What is solid-three?** solid-three is a port of [react-three-fiber](https://github.com/pmndrs/react-three-fiber) to [SolidJS](https://www.solidjs.com/). It allows you to declaratively construct a [three.js](https://threejs.org/) scene with reactive primitives, just as you would construct a DOM tree in SolidJS.

- **🎯 Declarative Components**: Utilize three.js objects as JSX components
- **⚡ Reactive Updates**: Properties update reactively for efficient re-renders  
- **🎬 Animation Loop**: Built-in `useFrame` hook for smooth animations
- **👆 Event System**: Comprehensive pointer and mouse event handling
- **🔧 Extensible**: Easy to extend with custom three.js entities
- **🚀 Optimized**: Leverages SolidJS's fine-grained reactivity

> **Why Choose solid-three?** Unlike imperative three.js code, solid-three lets you describe *what* your scene should look like, not *how* to build it. Combined with SolidJS's reactive system, you get automatic updates and optimal performance.

## Why Choose solid-three?

| Feature | solid-three | Pure three.js | react-three-fiber |
|---------|-------------|---------------|-------------------|
| **Reactivity** | Fine-grained (SolidJS) | Manual updates | Re-render based |
| **Bundle Size** | Smaller | Largest | Medium |
| **Learning Curve** | Moderate | Steep | Moderate |
| **Performance** | Excellent | Good | Good |
| **TypeScript** | Full support | Full support | Full support |
| **Ecosystem** | Growing | Mature | Mature |

> **Key Advantage**: SolidJS's fine-grained reactivity means only the specific properties that change get updated, not entire components.

## Quick Start

Choose your preferred approach for creating three.js components:

```tsx
import { Canvas, createT } from "solid-three";
import * as THREE from "three";

const T = createT(THREE);

function App() {
  return (
    <Canvas>
      <T.AmbientLight intensity={0.5} />
      <T.DirectionalLight position={[10, 10, 5]} />
      
      <T.Mesh>
        <T.BoxGeometry args={[1, 1, 1]} />
        <T.MeshStandardMaterial color="orange" />
      </T.Mesh>
    </Canvas>
  );
}
```

<details>
<summary>Choosing Between Entity and T</summary>

**Use Entity when:**
- Building libraries or reusable components
- Working with dynamic object types
- You want to avoid creating a namespace

**Use T when:**
- Building applications
- You want better TypeScript autocomplete
- You prefer component-style syntax

</details>
